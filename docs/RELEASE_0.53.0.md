# CPFormal v0.53.0 — Causal inheritance of positional carry

## Scope

This release freezes a certificate-bearing formalization of the arithmetic
tower

```text
positional carry
→ positional addition
→ multiplication
→ natural power.
```

The formal result distinguishes two notions that must not be conflated:

1. whether the carry pattern is explicitly displayed by the notation of a
   carrier; and
2. whether the carrier has certified operational ancestry from positional
   carry.

The word `causal` has the precise internal meaning defined by
`CausalCompressionSystem`: primitive instantiation, a path whose edges contain
mathematical compression witnesses, and a nonconstant observable action at the
target carrier.

This release does not use primality, oddness, a distinguished camera, a
complex parameter, or an external causal postulate. The concrete arithmetic
results hold for every nondegenerate positional base `b > 1`.

## Generic certificate-bearing language

`CPFormal.Logic.CausalCompression` introduces a neutral framework with the
following data:

```text
Pattern
Carrier

Output
eval
PrimitiveWitness
CompressionWitness
ExplicitlyDisplays.
```

A `CompressionPath` is not a bare reachability graph. Every non-reflexive edge
contains a nonempty value of the concrete system's `CompressionWitness` type.

The central predicates are:

```text
Reinstantiates pattern carrier

OperationallyNontrivial carrier

CausallyPresentIn pattern carrier

HiddenButCausallyPresentIn pattern carrier

GeneratedBy pattern.
```

Their meanings are:

- `Reinstantiates` requires a primitive source witness and a certified
  compression path to the target;
- `OperationallyNontrivial` requires two inputs on which the carrier's
  observable has different outputs;
- `CausallyPresentIn` combines certified ancestry with operational
  nontriviality;
- `HiddenButCausallyPresentIn` additionally records that the pattern is not
  explicitly displayed at the carrier's surface;
- `GeneratedBy` requires certified ancestry for every carrier of the specified
  system.

The kernel proves composition and inheritance through certified paths:

```text
CompressionPath.trans
reinstantiates_of_primitive
reinstantiates_of_compression
reinstantiates_of_path
causallyPresentIn_of_path
causallyPresentIn_all_of_generatedBy
hiddenButCausallyPresentIn_of_witness.
```

The generic framework does not postulate that all mathematical structures are
generated by one pattern. A concrete instance must supply its own primitive
witnesses, compression certificates, and nonconstant evaluations.

## Carry as a value-preserving scale transition

The arithmetic instance represents the pre-normalization state of one unit of
carry by

```text
b units at depth k
```

and the normalized state by

```text
1 unit at depth k + 1.
```

The kernel proves:

```text
positionalUnitCarry_preserves_value
```

which is the exact identity

```text
b * b^k = 1 * b^(k+1).
```

It also proves:

```text
positionalUnitCarry_changes_configuration.
```

Thus the two positional configurations are distinct even though their
represented natural-number value is identical.

This theorem records carry as a change of positional coordinates and scale. It
does not insert additional numerical value into the represented quantity.

## Exact carry certificate for positional addition

For positive base `b`, the units-column decomposition of a natural-number sum
is represented by

```text
positionalAdditionDigit b (x,y)
  = residueAtDepth b 1 (x+y)

positionalAdditionCarry b (x,y)
  = quotientAtDepth b 1 (x+y).
```

The kernel proves the exact reconstruction theorem:

```text
positionalAddition_reconstruction
```

with statement

```text
x + y
  =
residueAtDepth b 1 (x+y)
  + b * quotientAtDepth b 1 (x+y).
```

It separately proves the saturation criterion:

```text
positionalAdditionCarry_pos_iff_saturated
```

with statement

```text
0 < positionalAdditionCarry b (x,y)
  ↔
b ≤ x + y.
```

For `b > 1`, these results and the canonical digit bound are packaged in the
semantic certificate

```text
carryToAdditionCertificate :
  PositionalCarryCompression
    b additionEval (positionalAdditionCarry b).
```

This is an exact quotient-and-residue reconstruction, not a naming convention
or an unsupported edge in a dependency graph.

## Multiplication and power as certified iterations

The release introduces `IterationCompression`, whose certificate stores both
the zero law and the successor law of an iterated operation.

Multiplication receives the certificate

```text
additionToMultiplicationCertificate
```

containing

```text
a * 0 = 0
a * (n+1) = a*n + a.
```

Natural exponentiation receives the certificate

```text
multiplicationToPowerCertificate
```

containing

```text
a^0 = 1
a^(n+1) = a^n * a.
```

These certificates do not assert numerical equality between addition,
multiplication, and exponentiation. They record the exact recursive laws by
which the later natural-number operation packages iteration of the preceding
one.

## Main causal-inheritance theorem

For every base `b > 1`, the kernel proves:

```text
positionalArithmetic_generatedByCarry
```

and

```text
positionalArithmetic_operationallyNontrivial.
```

The principal theorem is:

```text
positionalCarry_causallyPresent_through_arithmeticTower.
```

It states that positional carry is `CausallyPresentIn` every carrier of the
explicitly modeled arithmetic tower.

The release further proves:

```text
positionalCarry_hiddenButCausallyPresent_in_multiplication

positionalCarry_hiddenButCausallyPresent_in_naturalPower.
```

In this model, multiplication and natural-power notation do not explicitly
display the carry pattern, but both retain certified ancestry from the
primitive carry carrier and both act nontrivially on observable inputs.

The hidden-presence conclusion uses the explicit-surface classification
provided by `arithmeticExplicitlyDisplays`; it is not an unrestricted theorem
about every possible notation for multiplication or exponentiation.

## Carry mass and quadratic rigidity

The arithmetic tower is connected to the already kernel-checked positional
mass results without redefining or externally inserting a mass.

For `b > 1`, the kernel proves:

```text
positionalCarry_mass_and_quadraticAmplitude
```

which combines

```text
uniformFiniteProbability
  (uniformCarryEvent (b^k))
    =
criticalMass b k
```

and

```text
(criticalAmplitude b k)^2
  =
criticalMass b k.
```

Here

```text
criticalMass b k = b^(-k).
```

For positive depth `k`, the existing quadratic-rigidity theorem gives:

```text
(branchAmplitude b sigma k)^2
  =
criticalMass b k
  ↔
sigma = 1/2.
```

The consolidated theorem

```text
positionalCarry_causalInheritance_mass_and_rigidity
```

records in one kernel-checked statement:

- hidden causal presence of carry in natural power;
- value preservation under carry normalization;
- uniform carry-event mass `b^(-k)`;
- the quadratic critical-amplitude identity;
- uniqueness of the exponent `sigma = 1/2` for the modeled branch amplitude.

The theorem does not identify `b^(-k)` pointwise with inverse-integer energy or
with a mass belonging to an unrelated operator.

## Base independence

The concrete causal-inheritance tower requires only

```text
1 < b.
```

It does not require:

- `b` to be prime;
- `b` to be odd;
- `b = 3`;
- a privileged camera;
- a complex coordinate;
- a zeta function;
- an analytic continuation.

The result is therefore uniform over every nondegenerate positional base
represented by the formal instance.

## Interpretation boundary

This release does not:

- prove that every mathematical object is generated by carry;
- prove that arithmetic operations cannot be defined without positional
  notation;
- turn the generic predicate `GeneratedBy` into a universal axiom;
- infer metaphysical or physical causation from the name
  `CausallyPresentIn`;
- treat recursive iteration as equality between different operations;
- assert an information-theoretic compression ratio;
- identify the carry-event mass `b^(-k)` pointwise with `n^(-1)`;
- derive an operator zero, spectral statement, or global analytic theorem from
  the arithmetic tower;
- use numerical experiments as proof premises;
- introduce a local `axiom`, `sorry`, or `admit`.

The ledger therefore keeps

```text
every mathematical system is generated by carry
```

at status `VISION`.

A future carrier can be promoted to a kernel-checked causal-inheritance result
only after its observable, primitive ancestry, nontriviality, and every
required compression certificate have been constructed.
